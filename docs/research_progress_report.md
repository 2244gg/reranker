# LastFM-1K 数据集去偏推荐研究进展汇报

**研究主题**：基于 LLM 推荐 + 后处理重排序的人群条件流行度去偏  
**实验对象**：LastFM-1K (Celma, 2010) 单曲监听数据集

---

## 1. 研究背景与目标

### 1.1 研究问题

大语言模型（LLM）在被用作推荐系统时存在两类偏差风险：
1. **流行度偏差（popularity bias）**：LLM 倾向于推荐主流热门内容，长尾物品被系统性低估。
2. **人群条件偏差（demographic bias）**：LLM 在 prompt 中得到用户性别/年龄等人口特征后，可能产生群体刻板印象式推荐。

本研究目标：在不重新训练 LLM 的前提下，设计**轻量级后处理重排序算法**，在保持推荐准确性的同时，显著提升长尾物品曝光度并缓解人群条件偏差。

### 1.2 重排序公式

\[
S_i = \alpha \cdot P_i + (1 - \alpha) \cdot (1 - B_i)
\]

| 符号 | 含义 |
|---|---|
| \(P_i\) | LLM 给出的偏好分数（按排名衰减得到） |
| \(B_i\) | 物品 \(i\) 在用户所属人口分组中的相对流行度（0 = 完全冷门，1 = 该分组内最热门） |
| \(\alpha\) | 信任 LLM 排序的权重；动态计算，在 \([\alpha_{\min}, \alpha_{\max}]\) 之间根据用户主流度浮动 |

直觉：\(\alpha\) 越大越信任 LLM，\(\alpha\) 越小越激进去偏（让冷门曲翻身）。

## 2. 数据集

### 2.1 LastFM-1K 概况

- 来源：Celma 2010
- 用户：993 人（profile 文件）
- 监听事件：约 19,150,000 条（2.5GB 原始 TSV）
- 字段：每条记录 = (用户, 时间戳, 艺人 ID, 艺人名, 单曲 ID, 单曲名)


## 3. 工作进展（按阶段）

### 阶段一：物品粒度从「艺人」改为「单曲」

#### 起点

原本希望在 LastFM-1K 上做**艺人级**实验：
- 物品 = 艺人名（如 "Radiohead"）
- 推荐输出 = 用户可能喜欢的艺人列表
- 流行度表 = 每位艺人在性别/年龄分组中的相对流行度

早期艺人级探索性结果（n=5、n=100 的 α 消融），未形成完整结论，原因是无法通过数据集判断用户对单个艺人的评价。

#### 改造

向用户推荐**单曲**而非艺人，原因：
1. 单曲是用户实际消费的最小单位，推荐价值更直接
2. 单曲粒度的去偏问题更具挑战性（数据更稀疏，B 值分布更极端）
3. 论文文献中音乐推荐评估主流是 track-level

#### 实施

| 维度 | 艺人级（原） | 单曲级（新） |
|---|---|---|
| item_id | `"Radiohead"` | `"Radiohead \|\|\| Creep"` |
| title（呈现给 LLM） | `"Radiohead"` | `"Creep - Radiohead"` |
| Prompt 模板 | 通用音乐模板 | 单曲专用模板（强制 `Track - Artist` 格式） |
| 入表单曲数 | ~5,000 | **272,769** |
| 流行度列数 | 16 | 16（含 Unknown 切片） |

适配器以 `granularity` 开关在两种模式间切换，向后兼容原艺人级实验。

### 阶段二：年龄分桶重设计

实测发现原 3 桶年龄方案 (Youth/Middle/Senior) 在 LastFM-1K 上严重失衡：

| 桶 | 边界 | 用户数 | 状况 |
|---|---|---|---|
| Youth | <25 | 162 | 健康 |
| Middle | 25-44 | 119 | 健康 |
| **Senior** | ≥45 | **4** | **极稀疏，B 值仅有 0.5/1.0 两档** |

将 Senior 合并入 Middle，得到平衡 2 桶方案：

| 桶 | 边界 | 用户数 |
|---|---|---|
| Youth | <25 | 162 |
| Middle | ≥25 | 123 |
| **Unknown** | 缺失 | **708**（最大桶） |

### 阶段三：v2 重排序算法

在迷你实验（30 用户）中观察到原算法在 LastFM-1K 单曲粒度上表现不佳：

- NDCG@20 下降 5-9%
- 长尾曝光（APLT）几乎无提升
- MRR 下降 7-15%

诊断后发现两个症结：
1. **B 矩阵分布过于偏斜**：272K 单曲中 max=224，绝大多数 \(B<0.05\)，导致 \((1-B)\approx 1\) 几乎到处一样，"长尾奖励"项失去区分度。
2. **早位精确度被破坏**：算法对所有候选统一排序，LLM 给出的精确头部命中常被中段冷曲挤下。

**v2 改进**：

| 改进 | 描述 |
|---|---|
| **A. Rank-normalized B** | 把每个分组列内的 \(B\) 值替换为该列内的分位数排名（0-1 均匀分布），让 \((1-B)\) 真正分辨中段与尾段 |
| **C. Top-K Protect** | 锁定 LLM 原始排序的前 5 位，只对第 6-30 位做重排序，merge 后输出 top-20 |

### 阶段四：评估指标补齐

原本只用准确性指标（Precision/Recall/HitRate/MRR/NDCG），但流行度去偏研究的标配指标是 APLT、Coverage、Gini 三件套（Abdollahpouri et al., 2017）。本研究新增：

| 指标 | 公式 | 取向 |
|---|---|---|
| **APLT (slice)** | top-K 中在用户人口圈子内 \(B<0.2\) 的占比 | 越高越好（去偏目标） |
| **APLT (neutral)** | top-K 中在全库 \(B<0.2\) 的占比 | 越高越好 |
| **Coverage** | 跨用户的唯一推荐物品数 / 库总数 | 越高越好（多样性） |
| **Gini** | 推荐频次分布的基尼系数 | 越低越好（公平曝光） |

## 4. 当前实验结果（n=30 迷你）

### 4.1 v2 算法 vs LLM 原始顺序（无重排序）

下表为 30 用户迷你实验在 4 个场景下的均值对比。

#### 准确性指标（rerank 略输，符合预期）

| 场景 | HitRate@20 | NDCG@20 | MRR | 解读 |
|---|---|---|---|---|
| **gender** | 0.733→0.724 | 0.401→0.390 | 0.465→0.459 | 几乎守住 |
| **age_group** | 0.800→0.786 | 0.477→0.461 | 0.478→0.464 | 同上 |
| **gender+age** | 0.700→0.677 | 0.389→0.359 | 0.374→0.360 | 同上 |

#### 长尾曝光指标（rerank 大幅赢，去偏目标）

| 场景 | APLT (slice) | APLT (neutral) | Gini |
|---|---|---|---|
| **gender** | 0.515 → **0.727** (+41%) | 0.505 → 0.712 (+41%) | 0.210 → **0.156** (-26%) |
| **age_group** | 0.462 → **0.675** (+46%) | 0.472 → 0.667 (+41%) | 0.190 → **0.140** (-26%) |
| **gender+age** | 0.505 → **0.715** (+42%) | 0.452 → 0.630 (+39%) | 0.205 → **0.139** (-32%) |

`protect_top=5` 显著保护了 LLM 给出的精确头部命中。

**v2 在长尾曝光指标上获得 +40% 绝对增益（APLT），在分布平等性上获得 -28% Gini 改善，同时仅以约 -3% MRR 与 Hit Rate 为代价**——这是一个站得住脚的 accuracy ↔ fairness 折衷。
